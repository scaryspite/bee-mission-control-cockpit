# Bee Mission Control Cockpit Design Notes

## Current State

The cockpit currently has working structure, panel rendering, assistant states, and basic styling.

This is not the final vibe.

Current risk:
- too generic dark dashboard
- too clean
- too balanced
- not enough lived-in ship computer
- not enough elder internet personality
- gremlin does not feel alive yet

## Target Feeling

Bee Mission Control should feel like:

- a private local command deck
- a lived-in ship computer
- an old utility interface that has survived too much
- a personal homepage from the elder internet
- a Toonami-style late-night space transmission
- a system that is funny because it is honest, not because it is unserious

## Not This

Avoid:
- corporate SaaS dashboard
- shiny sci-fi glassmorphism
- sterile productivity app
- cute mascot helper
- cluttered GeoCities chaos
- generic retro terminal
- anime waifu clutter
- fake AI authority

## Visual Ingredients to Add Later

- stamped utility labels
- small badges
- warning tape / caution-strip details
- CRT scanline texture
- dim monitor glow
- uneven panel hierarchy
- fake system readouts
- tiny status widgets
- personal command buttons
- gremlin sprite states
- “serious mode” visual lockout

## Usability Rules

The vibe is only successful if the page is still easy to use when tired.

Must preserve:
- readable text
- clear navigation
- clear source authority
- clear local/private status
- clear child app separation
- clear daily workflow

## Vibe Test

A design change passes if it makes the cockpit feel more like Bee without making the system harder to understand.

A design change fails if it only makes the page prettier.
